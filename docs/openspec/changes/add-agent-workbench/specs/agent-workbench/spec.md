## Purpose

定义 Agent 对话工作台的行为契约：面向「还没有想法」的用户，用多轮对话完成图片的生成、修改与变体，全过程规划透明、积分消耗明示，并与「经典生成」表单模式在同一页面内互为对照。

## ADDED Requirements

### Requirement: 双模式入口与对照
`/generate` 页面 SHALL 同时提供「经典生成」与「Agent 对话」两种模式入口，并以用户状态对照表述（「我有大致想法」/「还没想好，聊聊看」）。用户 SHALL 能在两种模式间随时切换，切换 SHALL NOT 丢失另一模式已产生的表单内容或对话/画布状态。经典模式的既有行为 SHALL 保持不变。

#### Scenario: 首次进入默认经典模式
- **WHEN** 已登录用户访问 `/generate`
- **THEN** 页面默认展示经典生成表单，同时可见 Agent 对话模式的入口卡片

#### Scenario: 模式切换保留状态
- **WHEN** 用户在 Agent 模式已有对话与画布内容后切到经典模式，再切回 Agent 模式
- **THEN** 原有对话记录与画布作品保持完整，不重置

### Requirement: 会话与消息持久化
系统 SHALL 为每个用户保存 Agent 会话及其全部消息（含用户消息、Agent 回复、工具调用轨迹与产出图片引用）。用户 SHALL 只能访问自己的会话与消息；访问他人会话或消息 SHALL 得到未找到响应。

#### Scenario: 会话延续
- **WHEN** 用户离开 Agent 工作台后再次进入同一会话
- **THEN** 历史消息、工具轨迹与画布作品完整恢复

#### Scenario: 越权访问
- **WHEN** 用户请求不属于自己会话的消息或图片上下文
- **THEN** 系统返回未找到，不泄露该资源存在性

### Requirement: 对话生图
用户 SHALL 能用自然语言（含模糊、口语化表述）发起生成请求。Agent SHALL 将其转化为专业画面说明后调用生图，生成的图片 SHALL 同时出现在对话流与画布。当用户表述过于模糊时，Agent SHALL 先提出澄清问题（并提供可点选的快捷回答）再生成，MUST NOT 在关键信息缺失时直接生成无关图片。

#### Scenario: 明确请求直接生成
- **WHEN** 用户输入「做一张高端护肤品的电商海报，极简风格」
- **THEN** Agent 展示任务规划后生成图片，结果出现在对话流与画布

#### Scenario: 模糊请求先澄清
- **WHEN** 用户输入「我想发个小红书，但完全没想好要什么图」
- **THEN** Agent 提出澄清问题并提供快捷回答选项，待用户选择后再生成

### Requirement: 过程透明与工具轨迹
Agent 的每一轮执行 SHALL 在对话流中展示：规划步骤（含各步骤完成状态与耗时）、工具调用（工具名、关键入参摘要、积分消耗）。工具调用明细 SHALL 默认收起、可展开。失败的工具调用 SHALL 展示失败原因。

#### Scenario: 查看工具调用明细
- **WHEN** 用户点击对话中的工具调用卡片
- **THEN** 卡片展开显示该次调用的提示词或指令全文

#### Scenario: 工具调用失败
- **WHEN** 生图服务不可用导致工具调用失败
- **THEN** 对话流展示失败步骤与原因，本轮不扣积分，Agent 以自然语言告知用户可稍后重试

### Requirement: 多轮改图
用户 SHALL 能选中画布上的任意图片作为编辑对象，并以自然语言下达修改指令。系统 SHALL 基于选中图片执行图像编辑生成新版本，新版本 SHALL 在画布标注来源（基于哪张图哪个版本），原版本 SHALL 保留。未选中图片时用户下达修改指令，Agent SHALL 明确告知需要先选中或引导选择，MUST NOT 对错误对象执行编辑。

#### Scenario: 选中后改图
- **WHEN** 用户选中「图 1 v1」后输入「背景换成樱花色调」
- **THEN** 系统生成新图片「图 2 v2」，画布标注「基于 图 1 v1 修改」，图 1 保留

#### Scenario: 未选中时要求改图
- **WHEN** 画布有图片但用户未选中任何一张，输入「把背景换成樱花」
- **THEN** Agent 自动选中最近一张图并向用户确认编辑对象，或提示用户先选择

### Requirement: 批量变体
用户 SHALL 能对选中的画布图片发起变体生成。变体 SHALL 保持主体构图一致、按明确差异方向（如配色）生成，每个变体计为一次独立生成并单独计费。

#### Scenario: 生成两个配色变体
- **WHEN** 用户对选中图片说「给这张图生成两个不同配色的变体」
- **THEN** 画布新增两个标注「变体」的作品，均标注基于原图，共扣 2 积分

### Requirement: 积分计费与余额保护
Agent 模式下的每次图片生成与每次编辑 SHALL 各扣 1 积分（与经典模式一致），变体按个数累计。工具调用展示的积分消耗 SHALL 与实际扣减一致。余额不足时系统 SHALL 在执行前拦截并引导购买，MUST NOT 出现已扣减未产出或已产出未扣减的账实不符。

#### Scenario: 余额不足拦截
- **WHEN** 积分为 0 的用户在 Agent 模式发起生成
- **THEN** Agent 提示余额不足并给出购买积分入口，不调用生图工具

#### Scenario: 失败不扣分
- **WHEN** 图片已开始生成但因服务错误失败
- **THEN** 本轮不扣积分，失败步骤在对话流中可见

### Requirement: Agent 大脑适配与模拟模式
Agent 的大脑（规划用 LLM）SHALL 通过 OpenAI 兼容接口接入并可由环境变量切换提供商与模型。系统 SHALL 提供模拟大脑模式（类似计费的 mock provider 先例）：不依赖外部 LLM 即可完整走通对话、工具调用与画布交互，用于本地开发与自动化测试；生产环境未显式允许时 MUST NOT 启用模拟大脑。

#### Scenario: 模拟模式全链路
- **WHEN** 环境配置为模拟大脑且用户走完「生成→改图→变体」流程
- **THEN** 对话、工具轨迹、画布与积分扣减行为与真实模式一致

#### Scenario: 生产环境禁用模拟大脑
- **WHEN** 生产环境未显式允许模拟大脑
- **THEN** Agent 接口拒绝以模拟大脑运行

### Requirement: 图像服务健康前置检查
Agent 发起生图或改图前 SHALL 检查图像服务可用性，不可用时以自然语言告知用户并停止本轮执行，不产生积分变动。

#### Scenario: 图像服务不可用
- **WHEN** 图像中继服务返回不可用且用户发起生成
- **THEN** Agent 回复服务暂不可用提示，规划步骤标记失败，积分余额不变
